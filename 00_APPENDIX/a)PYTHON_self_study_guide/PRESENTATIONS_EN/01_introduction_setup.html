Choose the installed environment

The primary course route uses the working MININET-SDN VirtualBox appliance. Run Linux commands in the guest, normally through SSH on Windows loopback port 2222. The WSL2 route is a separately documented alternative.

VM or native WSL Engine

Docker and Python run inside the selected Linux environment. docker info checks daemon access; docker --version checks only the client.

Optional Portainer

The course setup maps host loopback 9050 to container HTTP 9000. Access from Windows into the VM requires a tunnel or forwarding rule. Existing personal credentials are preserved.

python3 --version
docker context show
docker info

🧪 Experiment: First Python Script

🔬 Verifying the Working Environment

We will run the first exercise to verify that everything is configured correctly. This experiment takes approximately 5 minutes.

1

Open the Linux lab terminal

Use SSH to the VM, or the selected Ubuntu distribution if you follow the WSL route

🎯 Purpose: All tools are installed within this Linux environment

2

Navigate to the lab folder

cd $HOME/COMPNET-EN

🎯 Purpose: The command assumes the repository was cloned into your Linux home directory

3

Run the ping exercise

python3 "00_APPENDIX/a)PYTHON_self_study_guide/examples/05_ping_latency.py" --host 127.0.0.1 --count 3

🎯 Purpose: Verify that Python and the networking modules work correctly

4

Observe the result

You should see latency statistics (RTT)

🎯 Takeaway: Python invokes Linux ping and parses its observations; times depend on the machine

00_APPENDIX/a)PYTHON_self_study_guide/examples/05_ping_latency.py (expected output)

python3 "00_APPENDIX/a)PYTHON_self_study_guide/examples/05_ping_latency.py" --host 127.0.0.1 --count 3

Quiz 2: Working Environment

Question 2 of 2

What is the main purpose of using Docker in networking labs?
Hint 1/3

Docker is a containerisation technology. What does containerisation enable in the context of computer networks?

Hint 2/3

In our labs we run DNS, HTTP and FTP servers. How could we run them without installing these services directly on our machine?

Hint 3/3

Docker enables service isolation through containers. This allows us to simulate an entire network with different servers, each running in its own container.
